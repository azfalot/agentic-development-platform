# Propuesta inicial de comercialización

El proyecto puede evolucionar hacia un producto de gobernanza para equipos que usan agentes de programación y necesitan límites, evidencia y revisión humana. La alpha actual es una base técnica, no una promesa comercial.

## Problema y propuesta de valor

Equipos pequeños quieren aprovechar agentes sin perder control sobre alcance, gasto, cambios de Git y trazabilidad. AgentHub aporta contratos de tarea, worktrees aislados, presupuestos por tarea, verificación determinista y evidencia revisable.

## Público inicial

- Equipos de ingeniería con desarrollo Windows-first y uso de Codex.
- Consultoras que requieren evidencia de cambios para clientes.
- Equipos con políticas internas de aprobación y límites de gasto.

## Estrategia por fases

1. **Dogfooding real:** usar el producto en proyectos reales, registrar fricción y cerrar defectos reproducibles.
2. **Oferta asistida:** vender instalación, configuración de políticas y soporte, manteniendo el repositorio abierto como base de confianza.
3. **Producto de equipo:** añadir gestión centralizada de contratos, presupuestos, evidencia y aprobaciones, sin eliminar el control local.
4. **Integraciones opcionales:** GitHub y proveedores adicionales solo después de definir permisos, auditoría, coste y soporte.

## Modelo comercial a validar

- Open core: la base local y los contratos permanecen abiertos; las capacidades de equipo, soporte y administración pueden ser de pago.
- Servicios profesionales: auditoría de flujos de agentes, plantillas de políticas y formación.
- Suscripción de equipo: por usuarios activos o por proyectos gobernados, no por promesas opacas de autonomía.

## Condiciones antes de cobrar

- Repetir dogfooding en proyectos no sintéticos.
- Definir soporte, privacidad, telemetría opt-in y retención de evidencia.
- Publicar límites de producto, compatibilidad y política de seguridad.
- Validar que los costes de modelos se muestran por separado de la tarifa del producto.
- Consultar asesoramiento legal y fiscal para licencia, marca, facturación y tratamiento de datos.

La prioridad es demostrar ahorro de tiempo y reducción de riesgo con evidencia verificable; no automatizar más decisiones de las que el equipo pueda revisar.
